# 📖 คู่มือการใช้ Git พื้นฐาน (เข้าใจง่าย)

ไฟล์นี้สรุปคำสั่งที่จำเป็นสำหรับการจัดการโค้ดผ่าน Git ทั้งการบันทึก การส่งโค้ดขึ้น Server และการย้อนกลับเมื่อเกิดข้อผิดพลาด

---

## 1. ขั้นตอนพื้นฐาน (Add -> Commit -> Push)

เมื่อคุณแก้ไขโค้ดเสร็จแล้ว ให้ทำตาม 3 ขั้นตอนนี้:

### **ขั้นที่ 1: เลือกไฟล์ที่จะบันทึก (Add)**
เลือกไฟล์ที่คุณต้องการ "รวม" เข้าไปในการเก็บข้อมูลครั้งนี้
```bash
git add .
```
*(จุด `.` หมายถึงเอาไฟล์ทั้งหมดที่แก้ ถ้าอยากระบุแค่บางไฟล์ให้พิมพ์ชื่อไฟล์แทน)*

### **ขั้นที่ 2: บันทึกการเปลี่ยนแปลง (Commit)**
เขียน "ข้อความ" เพื่ออธิบายว่าเราแก้ไขอะไรไปบ้าง
```bash
git commit -m "ใส่ข้อความอธิบายการแก้ไขของคุณที่นี่"
```

### **ขั้นที่ 3: ส่งตัวเลขขึ้น GitHub/Server (Push)**
ส่งสิ่งที่บันทึกไว้ในเครื่องเรา ขึ้นไปยังเซิร์ฟเวอร์
```bash
git push origin master
```

---

## 2. การย้อนโค้ด (Revert/Undo)

หากทำพลาด หรืออยากย้อนกลับมาใช้เวอร์ชั่นเก่า:

### **ย้อนไฟล์ที่แก้ (ยังไม่ได้ Commit)**
ถ้าแก้ๆ อยู่แล้วพัง อยากให้ไฟล์กลับไปเหมือนเดิมก่อนแก้:
```bash
git checkout -- ชื่อไฟล์.ts
```

### **ยกเลิกการ `git add`**
ถ้าเผลอ `add` ไฟล์ที่ไม่ต้องการเข้าไป:
```bash
git reset ชื่อไฟล์.ts
```

### **ยกเลิกการ `Commit` ล่าสุด (แต่โค้ดที่แก้ยังอยู่)**
ใช้กรณี Commit ไปแล้วเพิ่งนึกได้ว่าลืมแก้อีกนิดหน่อย:
```bash
git reset --soft HEAD~1
```

### **ล้างทุกอย่าง ย้อนไปที่ Commit ล่าสุด (อันตราย! โค้ดที่แก้จะหาย)**
ใช้กรณีแก้มั่วจนเละ แล้วอยากเริ่มใหม่จากจุดที่ล่าสุดที่ Commit สำเร็จ:
```bash
git reset --hard HEAD
```

---

## 3. คำสั่งดูสถานะ (สำคัญมาก)

เช็คดูว่าตอนนี้มีไฟล์ไหนถูกแก้บ้าง หรือยังไม่ได้ Add:
```bash
git status
```

ดูประวัติการ Commit (ใครแก้อะไรไปเมื่อไหร่):
```bash
git log --oneline
```

---

## 💡 สรุปสูตรสำเร็จ (Cheat Sheet)

| การกระทำ | คำสั่ง |
| :--- | :--- |
| **บันทึกใหม่ทั้งหมด** | `git add .` -> `git commit -m "..." ` -> `git push` |
| **เช็คสถานะ** | `git status` |
| **ดูประวัติ** | `git log --oneline` |
| **ต้องการล้างที่แก้อยู่ให้สะอาด** | `git reset --hard HEAD` |
